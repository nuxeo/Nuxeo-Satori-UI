# adf-hx workarounds register

**What this file is for:** every place this codebase does something it would not otherwise do,
because `@alfresco/adf-hx-content-services` or `@alfresco/adf-core` requires it. It exists so the
cost of adopting adf-hx is countable rather than folklore.

**This file is gated.** Every marker in the codebase must have a row here, and every row naming a
code site must have its marker there — `scripts/review-guardrails.mjs`, `checkAdfHxWorkaroundIds()`,
run by the `guardrails` gate. A register with no gate decays the moment someone adds
another workaround, so it has one. It was watched fail on purpose before being trusted.

| Marker in code             | Category                                    |
| -------------------------- | ------------------------------------------- |
| `WORKAROUND(adf-hx): W<n>` | 1 — workaround for an upstream defect       |
| `MISSING(adf-hx): M<n>`    | 2 — feature adf-hx does not provide         |
| `REFUSES: R<n>`            | 3 — a port that refuses                     |
| `DEGRADED(adf-hx): D<n>`   | 4 — known-degraded, deliberately not hidden |

Rows whose site is a `.json` file carry **no marker**, because JSON cannot hold a comment. Those
are listed with `— (config)` and the gate does not look for a marker in them.

**Audiences differ per category, which is why they are separated:**

- **Category 1** is for leadership and for whoever plans an adf-hx upgrade. Read the
  **Removable?** column before quoting a count, and take the count from the table rather than from
  any sentence about it. "N workarounds" is not N things that eventually go away.
- **Category 2** is for product: these are features a customer sees, which upstream does not own.
  If we stop maintaining them, they disappear.
- **Category 3** is for whoever adopts the next component: it is the list of calls that throw.
- **Category 4** is for anyone who might otherwise report these as bugs. They are known.

Anything in here that is **upstream's fault** also appears in `docs/adf-hx-upstream-findings.md`,
which is written to be sent to the adf-hx team. This file is internal and includes things that are
nobody's fault.

Last updated: 2026-10-15. **adf-hx and adf-core are no longer installed:** NXSAT-635 removed the
POC routes and the bridge, NXSAT-636 adf-core's wiring, and NXSAT-637 the packages, merged together in PR #418 (NXSAT-638). The
register is now the record of what adf-hx cost. W1, W3 and W4 are the only rows still in effect,
and their causes are gone: what they left behind, the `ng-mocks` stub, the version pins and the
4 MB budget, is kept on purpose. The rows were kept against
`@alfresco/adf-hx-content-services@7.20.0-automate.292` and `@alfresco/adf-core@9.0.0`, on
`@angular/core@20.3.x`.

**For leadership: which of these are structural, by id rather than by total.** None is structural
any more. W4 was, until the ADF removal (PR #418) took its cause away; the 4 MB budget is kept.
W1 and W3 were removable when upstream changed, and their causes went with adf-hx and adf-core;
NXSAT-672 drops the stub and the pins. W9 is gone: the panels it sized were
removed from browse. W7, W8, W10, W11, W12 and W15–W18 are gone with the adf-hx browse and search
routes and the bridge, removed on 2026-10-14 (NXSAT-635). W2, W6, W13 and W14 are gone with
adf-core's wiring (NXSAT-636), and W5 with the last asset globs (NXSAT-636 and NXSAT-638).

**Why W2, W6, W13 and W14 could go, 2026-10-14 (NXSAT-636).** Each existed for adf-core alone.
W2's five methods were called only by adf-core's `TranslationService`, which nothing in our source
injects — only upstream components do. W6 fetched adf-core's and adf-hx's catalogues; the loader now fetches satori-ui's and the
app's own, pinned by `app-translate-loader.spec.ts`. W13 aliased a key inside the adf-hx catalogue
W6 fetched. W14 wrote our language into adf-core's preference, and injecting that service at boot
also set `<body dir>` and the CDK `Directionality` from a `textOrientation` nothing had set —
`dir="undefined"` measured on the base commit. Only our initializer sets the language now, from
configuration, on every boot: the `the configured language at startup` spec boots the real
`appConfig.providers` three times over a stale stored locale.

No derived totals, and the ids are listed so a reader can recount against the table rather than
trust a sum. The previous version of this paragraph said "14 workarounds, of which 7 are
structural" — and the paragraph at the top of Category 1 claimed those totals had been removed
while this one still carried them, which is the same defect one level down. Splitting the
structural group three ways is also the honest reason a single number was misleading: whether
W2, W10 and W14 count as structural depends on a judgement the number hides.

**W6 and W13 are not the same defect, and conflating them would hide the second.** W6 was a
catalogue that never loaded. W13 is a catalogue that loads correctly, holds the key, and is then
asked for that key under a different name. Seeding was necessary and not sufficient — W13 was
found only by reading the compiled template _after_ W6 was fixed and the string still did not
appear.

## Category 3 — Ports that refuse

Every one throws with a message naming the operation. **None returns a plausible empty value** —
`AGENTS/11-beta-program.md` §3 records a port silently discarding its sort as the defect pattern to
avoid, and an empty array from a model or upload call is the same mistake with a bigger radius.

They are **bound rather than left unbound** deliberately: eleven upstream services inject their
tokens at construction, so an unbound token stops those services — and every component touching
them — constructing at all.

## How to add a row

1. Put the marker in the comment at the site: `WORKAROUND(adf-hx): W<n> — one line on why`,
   using the next unused number in the relevant category.
2. Add the row here with the same ID.
3. Run `npm run beta:gate -- --gates guardrails`. It fails if the two disagree in either
   direction.
4. If the cause is upstream's, add it to `docs/adf-hx-upstream-findings.md` as well.

Do not delete a row when a workaround is removed. Strike it through and say which upstream version
fixed it — the history of what adf-hx cost is the point of the file.
