# Asset grid

The asset grid is the card view of a set of documents: a thumbnail, the document's name, and its
type as a pill, with a checkbox that appears on hover, on focus and while the card is selected. Use
it wherever a listing should be shown as cards rather than rows — the asset search screen's grid
view is one, and `nxs-document-list` is the table equivalent.

## Key features

- **It owns nothing.** No search, no selection, no navigation, no fetching. The host passes the
  cards and the selection and acts on the two events, so the same grid serves any query.
- **Thumbnail or icon.** A card with a `thumbnailUrl` shows it; a card with `null` shows its
  document-type icon and keeps exactly the same shape, so a page does not reflow as thumbnails land.
- **The whole card opens the document** — without the card being a control. A card holding a
  checkbox and a button cannot itself be a button (`nested-interactive`, WCAG 4.1.2), so the name is
  the control and its hit area is stretched over the card.
- **Nothing for no cards.** With an empty `assets` it renders nothing, leaving the empty state to
  the screen, which is the only place that knows whether the list is empty because of a filter,
  because of an error, or because nothing is there.

Every input is optional. `selectedIds` takes either a `Set` — `SelectionService.selectedIds()`
passes straight in — or a list. The grid's own words, its name and each checkbox's name, are
translated under `satori-components.asset-grid.*`, and `providePlatformEnglishFallback()` supplies
the English when your catalogue does not.

## Where its data comes from

Nothing. Build an `NxsAssetCard` per document from a search result: `id` from `uid`, `name` from
`dc:title`, `type` from `ecm:primaryType`, and `icon` from `docTypeIcon()`.

`thumbnailUrl` is an **object URL the host owns**. Fetch the thumbnail rendition through the
authenticated client and pass `createObjectURL()`'s result; the grid never makes or revokes one, so
revoke yours when the results change and on destroy. A Nuxeo URL does not work: the browser loads
an image with no credentials, so the request is unauthenticated and nothing appears. A host that
would rather not own URLs at all can pass `null` for every card and place `nxs-thumbnail`, which
fetches and caches its own.

Both tables work the same way, and the reason is worth knowing because it is easy to get wrong: a
custom property **declared on `:host`** is set on the grid element itself, so it beats the same
property inherited from an ancestor. Every knob here is therefore written as a `var()` fallback at
the point it is used and declared nowhere, which leaves both overrides working — the media query a
screen puts on the box around the grid, and the `theme.tokens` a customer ships, which
`AppThemeService.applyTheme()` writes inline on `<html>` and which the grid inherits.

## Accessibility

- **A named list.** The grid is a `list` of `listitem`s, named "Assets" unless you give it a
  `label`, so a screen reader announces how many results there are instead of reading a run of
  unrelated controls.
- **Named checkboxes.** Each is named "Select &lt;document&gt;", bound through Material's own
  `[aria-label]` so the name lands on the `input` that carries the checkbox role — `[attr.aria-label]`
  on the `mat-checkbox` host does not reach it.
- **Decorative thumbnails.** `alt=""`, because the name button beside the image already says which
  document it is.
- **The checkbox is reachable.** It is hidden until hover **or focus**: `:focus-within` is as
  load-bearing as `:hover`, since without it a keyboard user lands on a `visibility: hidden` control.
- **Keyboard.** Checkbox and name are ordinary controls: **Tab** reaches them, **Space** ticks the
  checkbox, **Enter** or **Space** presses the name. The focus ring is drawn on `:focus` as well as
  `:focus-visible`.
- **Reduced motion.** The hover transitions are dropped under `prefers-reduced-motion`.
