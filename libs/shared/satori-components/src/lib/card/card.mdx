# Card

The card is one item in a grid of cards, such as a document in the card view of a folder or of
search results: its thumbnail, its title and type, a checkbox to select it, and the actions the
page offers on it. Use it for a grid a user scans by eye. For a list a user sorts and compares,
use the document list.

## Key features

- **Opens from anywhere on it.** With an `openHandler`, the title is a button whose area covers
  the whole card, so a click on the thumbnail opens the item too.
- **Controls of their own.** The checkbox, the corner action and the actions at the foot sit above
  that area as separate controls, never inside the button.
- **Selectable when named.** A `selectionLabel` adds the checkbox, named by it; `selectionHandler`
  hears its new state. Without a label the card is not selectable.
- **Your thumbnail and actions.** The page passes templates for the media, the corner action and
  the actions, and they render with the page's own data and handlers.
- **Fills its cell.** Every card in a grid row is as tall as the tallest.
- **Outlined only when it opens.** It is a Material card, outlined when it has an `openHandler`
  and filled when it opens nothing, because an outline says a surface can be pressed. Hover and
  selection take the theme's primary colours.
- **Replaceable by ID.** It is registered as `nxs.primitives.card`, so your own card can take its
  place on every screen that renders the ID.

## Usage

export const usageTs = `import { NxsCardComponent, NxsThumbnailComponent } from '@nuxeo/satori-platform/components';

readonly cards = computed(() =>
  this.documents().map((doc) => ({
    doc,
    open: () => this.openDocument(doc),
    select: () => this.selection.toggle(doc.uid),
  })),
);`;

export const usageHtml = `@for (card of cards(); track card.doc.uid) {
  <ng-template #thumbnail>
    <nxs-thumbnail class="acme-thumbnail" [documentId]="card.doc.uid">
      <mat-icon svgIcon="file" />
    </nxs-thumbnail>
  </ng-template>
  <nxs-card
    [heading]="card.doc.title"
    [subheading]="card.doc.type"
    [selected]="selection.isSelected(card.doc.uid)"
    [selectionLabel]="'acme.select-item' | translate: { name: card.doc.title }"
    [selectionHandler]="card.select"
    [openHandler]="card.open"
    [media]="thumbnail"
  />
}`;

Every input is optional. `heading`, `subheading` and `selectionLabel` take text you have already
translated. `selected` is a bare attribute. The handlers are functions, made once per item rather
than in the template, so the card's inputs keep their identity between change detection runs.
`media`, `headerAction` and `actions` are `TemplateRef`s, rendered where you declared them, so they
read your component's own data. The card has no outputs. It needs no providers.

Place it in a template by its selector, or render the ID `nxs.primitives.card`
(`NXS_PRIMITIVE_IDS.card`) through `lib-extension-outlet` with the same inputs, as browse and search
do. The outlet sets inputs and binds no outputs, which is why everything the card takes is an input.
Give the outlet `display: contents` in a grid, so the card it renders is the grid item. A
replacement you register under the ID implements `NxsCardInputs`. With
`provideNxsSatoriComponents()` the ID renders Satori's interactive card instead, through the wrapper
in `@nuxeo/satori-platform/components-satori`; the same inputs, and the same thing a click does.

## Where its data comes from

The card loads nothing. Your component passes the text, the selection state and the handlers. The
thumbnail is whatever your media template renders: in the application, `nxs-thumbnail`, which
fetches the document's rendition through the platform's signed-in client. Nuxeo decides what the
user may open or select; the card only shows what your component passes.

**In these stories** no request is made: the media is the document-type icon a thumbnail shows
while it loads, and the text is the English an application would pass.

## Accessibility

- **One control to open.** The title is a native button, named by the title. Its area covers the
  card for pointer users; keyboard and screen reader users reach it as a button.
- **No nested controls.** The checkbox and the actions are siblings of the button, not inside it, so
  each is announced and operated on its own (WCAG 4.1.2).
- **Checkbox.** A native checkbox inside Material's, named by `selectionLabel`. A label of only
  spaces or invisible characters counts as none, and no checkbox renders.
- **Shown on focus.** The checkbox and the actions are faded until the card is hovered, focused or
  selected, never hidden, so they stay in the tab order; focusing one shows it.
- **Focus ring.** The title draws a two-pixel ring in the theme's primary colour on focus.
- **Keyboard.** **Tab** moves through the checkbox, the title, the corner action and the actions;
  **Enter** or **Space** presses the one focused.
