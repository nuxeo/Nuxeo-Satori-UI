# Document reference input

The document reference input finds a document as the user types and returns a reference to the one
chosen, as Web UI's `nuxeo-document-suggestion` does. Use it for a property that points at another
document: a related contract, a parent case, a template.

## Key features

- **Searches the repository's full text** from three characters, twenty results at a time, 300
  milliseconds after the last key — Web UI's `default_document_suggestion` search.
- **Leaves out what a user should not pick:** hidden documents, versions and the trash. Narrow it
  further with `documentTypes`, such as `['File', 'Note']`.
- **Shows where each result is.** Its type icon, title and path, so two documents with one title
  can be told apart.
- **Only a document the search returned.** Typing after a choice clears it, and text typed and not
  chosen is an error on the form, `nxsChooseFromList`.

`label` is the only required input. The value is an `NxsDocumentReference` — `uid`, `title`, `type`
and `path` — or `null`; store `uid` in the property. The input needs the platform's `NuxeoApiBase`.
Its statuses and the clear button's name are translated under `satori-components.pickers.*`;
`providePlatformEnglishFallback()` supplies the English. It has no registered ID: place it in a
template by its selector.

## Where its data comes from

The input runs the NXQL query of Web UI's `default_document_suggestion` page provider through
`NuxeoApiBase.nxqlSearch`: a full-text prefix match on what was typed, excluding hidden documents,
versions and trashed ones. `nxsDocumentSuggestionQuery()` builds it; the term and each type are
escaped, so they stay text in the query. The search runs with the application's sign-in, so Nuxeo
returns only documents the user may read.

**In these stories** `NuxeoApiBase` is an in-memory fake that matches three documents by title.

## Accessibility

- **A combobox.** The input is named by its label; the arrow keys move through the results and
  **Enter** chooses one. **Escape** closes the list.
- **Each option names the document and its location.** The type icon is hidden from assistive
  technology; the title and the path are read as separate words.
- **Statuses are announced.** The number of results, "No results" and a failed search are announced
  politely, and the hint for too few characters is the field's description.
- **Clear.** The x button that removes the choice is named "Clear".
