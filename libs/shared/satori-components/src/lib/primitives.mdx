# Primitives by registered ID

Ten components here are also in Satori's own component library: the avatar, the breadcrumbs, the
tag, the status tag, the rich tooltip, the error state, the tabs, the document toolbar's action bar,
the card and the empty state. Each one is registered under an ID. A screen that renders the ID, rather than the
component, shows whichever version the application registered: Satori's, when
`@nuxeo/satori-platform/components-satori` is installed and provided, or the built-in version
otherwise.

## Key features

- **One set of inputs per ID.** Every version of an ID takes the same inputs, so a screen passes
  the same values whichever is registered.
- **Callbacks and templates are inputs.** A screen renders an ID through `lib-extension-outlet`, which
  sets inputs and nothing else, so the tabs take their body template and selection callback, the
  action bar its action callback, the error state its retry callback, the card its open and
  selection callbacks and its templates, and the empty state its actions template, as inputs.
- **Satori when it is available.** The choice is made by the providers your application lists, not
  when the library is built and not by checking at run time.
- **Works without Satori.** Without access to GitHub Packages, leave Satori out: every ID still
  renders, using the built-in version.
- **Yours wins.** Register your own component under an ID, after the library's providers, and it
  replaces both.

The IDs are exported as `NXS_PRIMITIVE_IDS` from `@nuxeo/satori-platform/components`. Render one
with `lib-extension-outlet` from `@nuxeo/satori-platform/extensions`:

export const byIdHtml = `<lib-extension-outlet
  [componentId]="ids.tag"
  [componentInputs]="{ label: 'Invoice', color: 'purple' }"
/>`;

## Examples

### With Satori's components

List `provideNxsSatoriComponents()` after `provideNxsComponents()`: a later registration of the same
ID wins. Satori's components also need `provideSatori()` and Satori's translations in ngx-translate.

export const withSatorisComponentsTs = `providers: [
  provideAndConfigureSatoriUITranslations({ fallbackLang: 'en' }),
  provideSatori(),
  provideNxsComponents(),
  provideNxsSatoriComponents(),
];`;

### With your own tag

Register your component under the ID after the library's providers. It implements the ID's interface,
so screens pass it the same inputs.

export const withYourOwnTagTs = `import { Component, input } from '@angular/core';
import type { NxsTagColor, NxsTagInputs } from '@nuxeo/satori-platform/components';
import { provideSatoriExtensions } from '@nuxeo/satori-platform/extensions';

@Component({ selector: 'acme-tag', templateUrl: './acme-tag.html' })
export class AcmeTagComponent implements NxsTagInputs {
  readonly label = input.required<string>();
  readonly color = input<NxsTagColor>('gray');
}

providers: [
  provideNxsComponents(),
  provideSatoriExtensions({ components: { 'nxs.primitives.tag': AcmeTagComponent } }),
];`;

## Accessibility

- Both versions of an ID take their accessible names from the same inputs: the avatar's `label`, the
  rich tooltip's `triggerLabel` and the breadcrumbs' `label`. With a blank `label`, Satori's
  breadcrumbs keep the landmark name from Satori's translations.
- `lib-extension-outlet` adds no role or name to the component it renders. While a component
  registered with `import()` loads, the outlet shows a short loading message in a `status` region.
- Each component's page describes its keyboard behaviour. The rich tooltip differs most: both open on
  hover and focus, but only the built-in one also opens and closes when its button is activated.
