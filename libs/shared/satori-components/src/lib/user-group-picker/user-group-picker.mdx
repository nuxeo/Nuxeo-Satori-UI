# User and group picker

The user and group picker is a field that finds a user or a group as the user types, and returns the
one chosen. It is the field behind adding a permission, sharing a saved search and assigning a task,
as Web UI's `nuxeo-user-suggestion` is. Use it wherever a screen needs one principal that Nuxeo knows.

With `multiple`, choose several users and groups as chips. Each selection
stays while searching for the next; already selected entries are excluded from the suggestions.
If every match is already selected, the list shows the translated, non-selectable "No results" status.

## Key features

- **Searches as you type, as Web UI does.** From three characters, 300 milliseconds after the last
  key, so a one-letter term does not list the whole directory. Set `minChars` for a smaller one.
- **Users, groups or both.** `search` is `users-and-groups` (the default), `users` or `groups`.
- **Only a principal Nuxeo returned.** Typing after a choice clears it, so the value is never free
  text. Text typed and not chosen is an error on the form, `nxsChooseFromList`.
- **Says what is happening.** Too few characters, searching, no results and a failed search each
  show in the field or its list, and screen readers hear the number of results.
- **A form control.** Use it with `ngModel`, `formControl` or `formControlName`, or bind `value`
  two-way. `required`, a form's `Validators.required` and `disabled` work as on any field.

`label` is the only required input: the field's label, already translated. The value is an
`NxsPrincipal` — `id`, `label`, `kind` (`user` or `group`), `prefixedId` (`user:jsmith`) and, for a
user who has one, `email` — or `null`. Pass `id` to operations that take a username or group name,
and `prefixedId` to those that take the prefixed form.

The picker needs `HttpClient` and the platform's `DocumentDetailService` and `UserService`, which an
application using `@nuxeo/satori-platform/nuxeo-client` already has. Its hints, statuses and the
clear button's name are translated with ngx-translate, under `satori-components.pickers.*` and
`satori-components.user-group-picker.*`; `providePlatformEnglishFallback()` supplies the English. It
has no registered ID: place it in a template by its selector.

### Multiple values

Set `multiple` and bind an array: `readonly NxsPrincipal[]` through
`value` or the form control. Selection order is preserved, duplicates are excluded, and removing
the last chip emits `[]`. Without `multiple`, the value remains one principal or
`null`. Typing an unselected term is an `nxsChooseFromList` error in either mode, even when
other chips are selected. Resetting the form replaces all chips and clears the pending query.
Changing `multiple` refreshes the displayed selection and clears any pending query without
emitting a value change.

## Where its data comes from

For users and groups together the picker runs Nuxeo's `UserGroup.Suggestion` operation, as Web UI
does, through `DocumentDetailService.searchUsersGroups`. For users only it reads
`/api/v1/user/search`, and for groups only `/api/v1/group/search`, through `UserService`. Each request
carries the application's sign-in, so the server decides whom the user may see.

**In these stories** the services are in-memory fakes holding three principals, which answer after
150 milliseconds or refuse; nothing is sent to a server.

## Accessibility

- **A combobox.** The input is named by its label and controls a list of options, which the arrow
  keys move through and **Enter** chooses. **Escape** closes the list.
- **Each option names the principal and its kind.** The person or group icon is hidden from
  assistive technology; "User" or "Group", and the email address, follow the name as words.
- **Statuses are announced.** The number of results, "No results" and a failed search are announced
  politely. The hint for too few characters is the field's description.
- **Errors.** Once the field is left, an empty required field and text that was not chosen show an
  error under it, linked to the input.
- **Multiple chips.** The field label names the text input. **Left/Right** move between chips,
  **Backspace** on an empty input focuses the last chip; **Backspace/Delete** removes a focused
  chip. Each remove button is named "Remove" followed by the entry label. Disabling the form also
  disables the input and chip removal.
- **Clear.** The x button that removes the choice is named "Clear".
